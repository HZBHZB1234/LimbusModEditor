# Limbus Mod Editor 用户手册

本手册面向直接使用编辑器界面的模组作者，按真实操作顺序组织。所有窗口均为中文界面；
命令行（CLI）只覆盖探测/导入/导出三步，完整编辑流程请使用 GUI。

## 1. 三步出模组（傻瓜化流程）

1. **启动即引导**：上次项目会自动恢复；没有项目时弹出欢迎窗口
   （新建模组项目 / 打开项目 / 最近项目），主界面顶部提示条随时显示
   「下一步该做什么」，未打开项目时工作区有全屏引导。
2. **新建项目**：推荐「新建模组向导…」——只需填模组名，项目默认创建在
   程序目录 `projects/<模组名>/`；游戏目录、Unity 缓存、模组目录、FMOD DLL
   全部自动发现。
   - **共享设置（重要）**：这些目录是全局共享设置，保存在程序目录
     `config/shared-config.json`，所有项目共用，不再每个 .lmeproj 重复配置；
     旧项目文件里的目录值会在首次打开时自动迁移进共享配置（只填空位，
     手动值永远不会被覆盖）。手动调整集中在 **「设置…」** 窗口。
     - **游戏目录** — `LimbusCompany.exe` 所在目录（扫描 Steam 库自动定位）。
     - **Unity 缓存目录** — `LocalLow/Unity/ProjectMoon_LimbusCompany`
       （可能是 junction），按 `<外层键>/<内层键>/__data` 验证条目数。
     - **模组目录** — 真实加载器默认 `%APPDATA%\LimbusCompanyMods`。
     - **FMOD DLL** — 随包提供（发布包 `fmod/` 目录）时自动使用；也可在
       设置里手动指定目录（优先级最高），或依赖游戏自带运行库（仅解码）。
3. **自动扫描**：新建/打开的空项目会自动弹出「扫描游戏资源」窗口：
   引用模式索引全部 Unity 缓存 bundle（**不复制文件**），带进度与取消；
   已扫描条目走程序目录索引库（`cache/unity-cache-index.db`，SQLite，
   阶段 C 性能改造），再次扫描只做新鲜度检查与增量写回。个别损坏/未知
   bundle 会作为逐条诊断报告，不中断整体。索引库损坏删掉重建即可。
4. **编辑**：扫描完成后在资源视图里按容器目录浏览或直接搜索
   （类型/状态/排序/「仅显示容器内资源」筛选），选中资源即可替换 PNG、
   编辑 Sprite 元数据或 Unity 字段。首次编辑某个缓存 bundle 时编辑器自动
   把它复制进项目 `sources/cache/`（每 bundle 一次），此后缓存被游戏
   清理/换键也不影响你的项目。
5. **一键导出**：左栏「一键导出模组」把全部修改按真实加载器的 Carra2 布局
   （`<缓存外层键>/<内层键>/<pathId>.<类型表索引>`，逐条目 XZ）打包，
   默认输出到模组目录，放进即被加载器读取。导出报告列出逐资源状态与
   缓存对齐诊断。
6. **导出思路（自动分析）**：左栏「导出思路（自动分析）…」会先看项目里
   到底改了什么，再列出这次可用的出口（一键 Carra2 / Bank·Rebank 音频 /
   lang 文本补丁 / 导出向导 / 多格式导出 / 调试覆盖层），每条都写清区别与
   前置条件，推荐项排最前，点「用这个」直接走对应通道。点「一键导出模组」
   时若项目里同时存在音频或已登记的源模组（也就是有多种出口），会先弹出
   这份思路清单；只有纯 Unity 资源修改时直接导出，不打扰。

## 1.1 界面结构（页面模型）

主窗口是**三列布局**，没有顶部标签页：

```
[48 活动栏][220 共享侧边栏][* 页面宿主]
```

- **活动栏（最左，6 个入口）**：📦 资源工作台 / 🏦 音频工作台 /
  📝 文本工作台 / 🧩 静态数据工作台 / 📖 使用教程 / ⚙ 设置。
  点击即切换页面（选中项左侧有蓝色竖条）；`Ctrl+Tab` / `Ctrl+Shift+Tab`
  按活动栏顺序循环切页。页面常驻不销毁——切走再切回，搜索词、选中项、
  预览都还在。
- **共享侧边栏（第二列，所有页面共用、不消失）**：当前项目名、四个目录状态
  （游戏 / Unity 缓存 / 模组 / FMOD DLL）、「重新自动获取目录」、
  「① 获取资源 → 自动加载游戏资源」、「② 产出模组 → 导出思路 / 一键导出 /
  导出向导 / 导出全部」，以及「更多」里的打开模组目录 / 打开项目文件夹 /
  三个工作台入口 / 设置入口。
- **页面宿主（第三列）**：当前页面内容。未打开项目时，需要项目的页面
  （资源 / 音频 / 文本 / 静态）会显示「开始制作模组」引导；设置与教程页
  **无项目也能用**（共享目录随时可改，项目元数据段置灰并说明原因）。
- **资源工作台布局**：浏览列（搜索 / 筛选 / 列表或目录树）+ 可拖拽的
  `GridSplitter` + 预览列（默认 360px，最小 260px；浏览列最小 280px）。
  拖动把手调整占比，**双击把手复位默认**，占比持久化在
  `<程序目录>/config/ui-state.json`（删除该文件即恢复默认）。
  音频 / 文本 / 静态三个工作台复用同一套骨架。
- 导出向导 / 导出思路 / 扫描窗口 / 字段编辑等仍是模态对话框——它们是操作流，
  不是常驻页面。

## 1.2 快捷交互（拖放 / 右键 / 双击 / 快捷键）

- **拖放替换**（唯一的拖放行为）：选中一个图像资源（Texture/Sprite）后，
  把一张 PNG/JPG/TGA 拖进窗口，确认即登记为该资源的替换图。
  拖入 `.carra2`/文件夹等不再触发导入——资源只允许「自动加载」（见 §2）。
- **右键菜单**：资源视图右键 = 替换… / 编辑文本内容… / Unity 字段编辑 /
  十六进制预览 / 撤销此资源的修改 / 复制资源路径；列表与目录树共用同一份菜单，
  右键会先选中光标所在行/节点。
- **双击资源**：图像资源打开替换对话框，其余类型打开字段编辑（可用时）
  或十六进制预览。
- **撤销修改**：「撤销此资源的修改」会清除该资源上的替换文件、Unity 字段、
  Sprite 元数据三类编辑并还原状态（导出不再包含它）；项目 `edits/assets`
  里的暂存文件一并删除。
- **快捷键**：`Ctrl+F` 聚焦资源搜索框；`Esc`（搜索框内）清空搜索；
  `Ctrl+Tab` / `Ctrl+Shift+Tab` 按活动栏顺序循环切页。
- **长操作反馈**：加载窗口显示预计剩余时间；一键导出有进度窗口
  （阶段消息），导出报告可一键「打开输出位置」；侧边栏有
  「打开模组目录」「打开项目文件夹」快捷按钮。
- **列表友好化**：资源视图默认显示「名称 / 类型 / 状态 / 大小」四列，
  大小显示 KB/MB/GB，名称是容器里的游戏内文件名（不再是缓存键或 Path ID）；
  已修改行以金色文字高亮；悬停行显示完整容器路径；右栏「已修改资源」按
  资源数统计（同一资源重复替换只算一次）。
- **文本编辑**：选中文本 / JSON 资源后双击（或右键「编辑文本内容…」、右栏
  「编辑文本内容…」）打开内置编辑器；保存即登记为替换（与替换文件同一条
  可撤销 / 可导出管道），JSON 保存前校验并格式化，语法错误留在窗口里报错。

## 1.3 预览与属性（plan-01 / plan-05）

资源工作台右栏「预览」区按选中资源的类型自动切换形态，**未知类型也不空白**：

| 类型 | 预览形态 |
|---|---|
| Texture2D | 解码图像：棋盘格透明底、滚轮缩放、拖拽平移、双击复位；有替换时可在「替换图 ↔ 原图（缓存）」之间切换 |
| Sprite | 按图集裁剪区域合成的子图（同一套缩放/平移交互），信息行给出裁剪区域、逻辑 rect、pivot、纹理尺寸 |
| TextAsset / JSON | 行号 + 等宽正文；JSON 可解析时提供「文本 / JSON 树」切换（树节点上限 2000，超出注明） |
| 音频（Bank FSB / Unity AudioClip） | 波形包络 + 「▶ 试听」+ 时长/采样率/声道；缺 FMOD DLL 时说明缺什么，不假装能播 |
| MonoBehaviour / MonoScript | 只读字段树（脚本类名/程序集/GUID + 字段层级，编辑仍走「Unity 字段编辑」） |
| Mesh / AnimationClip / Font | 结构摘要卡（同「查看对象摘要」口径） |
| 其它 / 未知二进制 | 内嵌十六进制转储（前 4 KiB，偏移 + HEX + ASCII 边栏）+ 明确的「无专用预览」说明 |

- 预览下方是**「属性」折叠区**：类型 / 大小 / 修改状态 / 容器路径 / 所在 bundle，
  再按类型追加纹理（尺寸、格式说明、mipmap、是否 .resS 流式）、Sprite
  （rect/pivot/border/裁剪区域）、音频（压缩格式、声道、采样率、时长、FSB 结构）、
  文本（编码、字符数、JSON 可解析）、MonoBehaviour（脚本类、字段数）、
  Mesh/动画/字体摘要。**单项读取失败只在该行显示「（不可读：原因）」**，
  不会整块报错，也不用默认值补齐。
- 预览与属性都在后台线程读取，快速连续切换选中项时用代际守卫丢弃过期结果。

## 1.4 目录树（容器视图）

- 资源工作台中部默认是「🗂 目录树」，可切到「☰ 列表」。目录树完全基于
  Unity `m_Container` 表里的游戏内资源路径，像文件管理器一样逐段展开
  （目录显示「名称 (N)」）：
  - 找不到容器条目的对象归入「未命名资源」，叶子名退化为「类型中文 #编号」；
  - 树内容跟随当前搜索结果——先筛选再浏览，树里只有命中项；
  - 展开是惰性的：点开目录才生成下一层，全量索引也不卡顿；
  - 点选叶子与列表选中完全等效（右侧状态、按钮、预览同步），
    双击叶子 = 与列表双击相同的最常用动作。

## 2. 加载资源（只允许自动加载）

资源工作台**没有**「选择文件/文件夹加载」的按钮或输入框——资源只通过自动加载进入项目：

- **自动加载游戏资源**（侧边栏「① 获取资源」）：一键索引游戏 Unity 缓存中的
  全部 bundle（**引用模式，不复制文件**，重扫近瞬时）；新建/打开空项目时会
  自动弹出加载窗口并直接开始。已扫描条目走程序目录索引库
  （`cache/unity-cache-index.db`，SQLite），再次加载只做新鲜度检查与增量写回；
  个别损坏/未知 bundle 作为逐条诊断报告，不中断整体。
- 缓存目录缺失时提示条会说明原因（游戏启动过一次才会生成缓存），
  并指向「设置」页手动指定。
- 首次编辑某个缓存 bundle 时编辑器自动把它复制进项目 `sources/cache/`
  （每 bundle 一次），此后缓存被游戏清理/换键也不影响你的项目。
- **静态数据表默认不显示**：静态数据 bundle（`static_s1_0_assets_all_*`）里的
  资源默认从资源工作台隐藏，请到「🧩 静态数据工作台」编辑；勾选筛选行的
  「显示静态数据表」后此处也可见（旧项目重新加载一次资源即会打上标记）。
- 命令行（CLI）的 `import` 与「导出向导里选择源模组」仍然可用（它们是
  项目源登记通道，不是资源加载入口）。
- **从文件夹批量登记替换**（右栏「高级操作」）：选择一个文件夹，按文件名
  （不区分大小写）匹配资源并登记替换；默认跳过已替换的资源，完成后报告
  匹配数与未匹配文件清单。


## 3. Unity 对象检查与字段编辑（P1.1 / P1.2）

选中一个 Unity 资源后，右侧面板提供：

### 3.1 Unity 字段编辑
1. 点击 **Unity 字段编辑**。窗口顶部会显示脚本信息（m_Script 解析出的类名/命名空间/
   程序集；指向外部文件时显示其路径与 GUID）。
2. 字段树列出每个字段的真实序列化类型。默认只显示可编辑字段，勾选 **显示全部字段**
   可以看到数组、PPtr、字节数组等结构信息。
3. 编辑值并勾选 **应用** 列。保存前会做三层校验：
   - 类型校验（bool/整数/浮点/字符串按序列化类型解析）
   - 未知路径 / 不可编辑字段拦截
   - **指针语义校验（P1.2）**：`m_FileID` 不得超出外部引用表；同文件指针
     （`m_FileID=0`）的 `m_PathID` 必须指向真实存在的对象，否则报
     **InvalidTarget** 并标红该行
4. 校验失败时窗口保持打开、错误行标红，可修正后重试或取消。
5. 保存后修改以版本化编辑集存储（含原值、原值哈希、时间、作者、每字段修订号），
   构建时才会真正写入。

### 3.2 指针依赖显示与自动填充（P1.2 自动化）
- 窗口底部蓝色信息栏实时显示所有指针依赖的解析结果：
  - `空引用` — file/path 都是 0
  - `同文件 Path N（类型）` — 指向本 SerializedFile 内的对象
  - `外部文件 xxx Path N` — 通过外部引用表指向其他文件（附 GUID）
  - `无法解析` — 悬空指针（目标不存在）
- 选中某个 PPtr 的 `m_PathID` / `m_FileID` 行后，右下角下拉框会列出**同文件中与该
  指针声明类型匹配的对象**（例如 `PPtr<$GameObject>` 只列 GameObject）。选择对象后
  点击 **自动填充所选 PPtr**，即可自动写入 `m_PathID` 并把 `m_FileID` 归零，
  不需要手动查抄 Path ID。

### 3.3 查找引用者（P1.2）
- 资源面板的 **查找谁引用了此对象** 会扫描：
  - 独立 SerializedFile：本文件内所有指向该对象的指针
  - Bundle：包内**所有** SerializedFile，包括通过 `archive:/...` 形式跨文件引用
- 结果按 `Path N（类型）字段 xxx` 列出。修改/删除对象前先看这个列表：
  - 允许：把指向它的指针改成空引用（保留空引用策略）
  - 允许：重定向指针到另一个真实对象（重定向策略）
  - 拒绝：把同文件指针改成不存在的 Path ID（保存时被 InvalidTarget 拦截）

### 3.4 构建时引用完整性验证（P1.2）
- 字段预校验在构建前执行（`ValidateObject/BundleFieldEdits`），任何
  InvalidTarget/UnknownPath/ParseError 都会中止构建并给出完整原因列表。
- 每次重写 SerializedFile / 重打包 Bundle 之后，构建服务会做 **引用完整性 diff**
  （`VerifySerializedReferences` / `VerifyBundleReferences`）：对比重写前后每个对象
  的每个指针解析状态。任何"原本可解析 → 悬空"的回退都会使构建失败并列出具体字段，
  防止打包过程悄悄破坏引用。

## 4. 图片与图集

- 支持 Texture2D PNG 预览与替换（RGB24、RGBA32/ARGB32/BGRA32、DXT1/DXT5，DXT 为有损编码）。
- Sprite 支持 rect/pivot/border 元数据查看与编辑。
- 图集：**拆分图集** 从 SpriteAtlas 输出子图，**恢复图集** 按记录重新打包。
- ETC/ASTC 压缩格式解码与图集网格重写属于后续里程碑（P1.3/P1.4）。

## 4.1 对象摘要（P1.5，Mesh / 动画 / 字体）

选中 Mesh、AnimationClip 或 Font 类型的资源后，点 **「查看对象摘要」**：

- Mesh：子网格数、顶点数、顶点数据大小、索引缓冲大小；
- AnimationClip：旧版模式、采样率、动画类型（Legacy/Generic/Humanoid）；
- Font：字号、字符表条目数、内嵌字体数据大小、默认材质指向（同文件/外部文件）；
- 所有数值只来自该文件自己的类型树；某版本缺字段时在「未包含」清单中明确标注，
  绝不用默认值补齐；窗口内可复制文本或导出 JSON（`logs/` 外任意位置）。

## 5. 音频（Bank / FMOD）

- `.bank` 仅解析 RIFF/FEV/SNDH 索引层，不做专有格式逆向。
- **FMOD DLL 随包提供**（发布包 `fmod/` 下的 fmod64.dll / fsbank64.dll /
  libfsbvorbis64.dll，启动时按「程序目录\fmod → 程序目录 → 游戏目录」自动
  发现，无需配置）：配置后可 **导出当前音频 WAV**（FSB→WAV）、WAV→FSB
  替换与基于 WAV 的 `.bank` 重建。
- 手动指定的 DLL 目录（设置窗口）优先级最高；游戏自带运行库
  （`LimbusCompany_Data/Plugins/x86_64/fmodstudio.dll`）可承担解码。
- **「检测兼容性」（设置窗口内）**：无需加载 DLL 即可查看各 DLL 的
  位数（x64/x86）、文件版本、导出符号快照，以及解码与 FSB 编码
  接口是否齐全；结果按 DLL 指纹缓存（程序目录 `cache/fmod-probe.json`），
  目录变化后自动重新检测。32 位 DLL 会给出明确警告（本编辑器为 64 位进程）。
- 完整 FSB5 原样替换不需要任何 DLL。

## 5.1 音频工作台（🏦，plan-06）

活动栏 🏦 打开。布局与资源工作台同骨架（浏览列 + 拖拽把手 + 预览/编辑列）：

- **浏览列**：自动定位 `<游戏>/LimbusCompany_Data/StreamingAssets/Assets/Sound/
  FMODBuilds/Desktop`（未配置游戏目录时给出引导）；引用模式扫描全部 `.bank`
  （本机 1531 个，不复制文件），显示文件名 / 类型（事件 / 音频 / 加密 / 无法识别）/
  FSB 数 / 大小，支持文件名搜索与类型筛选，「重新扫描」可刷新。
- **样本表**：选中一个 bank 后列出样本（名称 / codec / 采样率 / 声道 / 时长 /
  大小）；事件 bank 显示「无 FSB 负载」并列出 RIFF 顶层块（STDT/STBL/HASH/DEL）；
  加密 bank 明确报错不解码。
- **试听 / 导出 WAV**：选中样本 →「▶ 试听」解码该样本在本机播放（临时文件，
  再点停止、切选或关窗自动清理）；「导出样本 WAV…」另存为可播放的 WAV。
  需要 FMOD DLL（随包 `fmod/`、设置里手动指定，或游戏自带运行库）。
- **用 WAV 替换**：选中样本 → 选一个 WAV → 该 bank 首次编辑时会被复制进项目
  `sources/banks/`，WAV 存进项目 `banks/<bank 名>/`，并登记一条 `fsb/<索引>`
  音频资源（与 Bank 导入管道同构）。导出时由 FSBANK 把 WAV 重新编码进 bank；
  **缺少 fsbank64.dll 时会明确报错，不会静默跳过**。
- **导出**：「导出整包 .bank…」（加载器按同名整包替换，无需编码器即可用）
  或「导出 .rebank…」（zip = `rebank.json` + `{fsb索引}/{样本名}.wav`，
  `base_bank` 为纯文件名，符合真实加载器语义）。两者默认输出到模组目录，
  **编辑器绝不写游戏目录**。
- 说明：.rebank 的 wav 文件名必须与加载器从原版 bank 解出的名字一致，
  否则加载器会跳过该条目（整包 .bank 是更稳的通道）。


## 6. 构建与调试

1. **导出模组（导出向导，P3.2）**：向导先识别源格式，再显示
   源格式→目标格式兼容性矩阵（不可用目标置灰并解释原因，例如 Lunartique→对象级
   Carra 需要有效 Unity SerializedFile）、项目概况（资源数/替换数/字段编辑数）与
   输出路径建议（选择目标后自动切换扩展名）。
2. **导出报告**：导出完成后显示逐资源状态（已应用 / 已跳过 / 保留未知）与诊断；
   「已跳过」的资源不会写进包，可按说明检查替换路径是否匹配。
   导出 Carra/Carra2 时若配置了 Unity 缓存目录，编辑器会逐外层键核对缓存中
   是否仍有对应 bundle（真实加载器按 `<缓存根>/<外层>/<内层>/__data` 匹配；
   游戏更新会更换外层键，失配的模组会被加载器静默跳过）——失配以
   「缓存对齐：…」诊断出现在报告中。
3. **构建调试覆盖层**：在 `builds/` 生成应用文件。
4. **应用并启动调试**：先备份游戏目录中被覆盖的文件到 `backups/`，再应用覆盖层并
   启动 `LimbusCompany.exe`。编辑器关闭时可恢复备份。
5. 所有构建输出统一经过事务写出（P0.2）：内容先写入临时文件再原子替换到目标；
   失败/取消时原文件保持不变、临时文件自动清理；目标被游戏占用时给出明确提示，
   请关闭游戏后重试。
6. **文本模组（lang 补丁）**：见 §6.2「文本工作台」——现在是一个常驻页面
   （📝），浏览活动语言目录、键值编辑并导出补丁；底层服务
   `LangTextPatchService` 的「目录差分」能力仍保留（CLI / 测试使用）。
7. **vanilla 基线判定（T3）**：导入 bundle 时，若项目已设置游戏目录且其中
   有官方 catalog（`StreamingAssets/aa/catalog.bin`），编辑器会只读解析
   catalog 并判定该 bundle 相对 vanilla 的状态（vanilla 一致 / 与基线不符 /
   不在 catalog / 基线未知），写入资源的 `catalogBaseline` 元数据并出现在导入
   诊断中（资源视图不再单列一列，避免技术性信息占位）。
   「与基线不符」通常意味着该缓存 bundle 已被模组补丁改写过。
8. **静态数据模组（.staticmod）**：见 §6.3「静态数据工作台」——现在是一个
   常驻页面（🧩），从 catalog 动态定位静态 bundle、浏览/搜索/编辑其中的
   TextAsset 静态表并导出 `.staticmod`。

## 6.2 文本工作台（📝，plan-07 / plan-10 重做）

活动栏 📝 打开，布局与资源工作台同一套骨架（浏览列 — 分隔条 — 编辑列）：

- **数据源**：`<游戏>/LimbusCompany_Data/lang`；读 `config.json` **动态**确定活动语言
  （本机实测为 `LLc-CN-LCTA`，官方为 `LLC_zh-CN`——一律跟随 config.json，
  不写死任何语言名），只处理活动语言目录 + 根级 `config.json`（其他翻译组目录不索引）。
  筛选行显示 lang 根、活动语言、文件总数与索引状态。
- **浏览列有两个视图**（右上角 `🗂 树` / `☰ 列表` 切换，默认树）：
  - 🗂 **树**：`lang 根 → config.json / 活动语言目录 → 子目录（StoryData 等）→ 文件`，
    逐层展开（展开时才生成下一层，几千个文件也不卡）；文件节点后面标注顶层键数与大小，
    非 UTF-8 文件明确标注「非 UTF-8」。
  - ☰ **列表**：扁平文件表（文件 / 键数 / 大小 / 状态），已修改的行金色高亮。
  - 两者都有筛选：`全部文件 / 仅已修改 / 仅非 UTF-8` + 「键数 ≥」。
  - 双击树里的文件、或单击列表里的行，都会打开该文件到编辑列。
- **搜索（文件名 / 键路径 / 值）**：搜索框 300ms 防抖 + 后台线程，结果出现在
  **独立的「搜索结果」视图**里（命中时才出现，不占常驻高度）；命中行显示
  类别（文件名 / 键 / 值）、命中位置（展平键路径）、片段与所属文件，
  **点击即跳转到文件并定位到该键**（编辑器树自动逐级展开并选中）；
  点「返回浏览」收起结果回到树。
- **编辑列**（共享 JSON 编辑器，树 + 原文双 Tab）：
  - **键值树**：按层**惰性展开**（对象/数组容器先显示 `N 个键`，展开才生成子层），
    选中叶子即可编辑并「应用修改」（字符串/整数/浮点/布尔/null 按原类型写回，
    类型不符给中文错误）；「删除此键…」确认后以 RFC6902 remove 进入补丁；
    「全部展开」展开当前子树，**没有旧的 5000 行截断**——几万个键的表也能完整查看。
  - **原始 JSON**：完整文本编辑，保存前校验合法性，非法 JSON 会被拒绝并保留原编辑集。
  - 「还原此文件」把该文件移出编辑集（lang 目录从未被改动）。
  - 底部「差异摘要」显示与官方版本（vanilla 快照）之间的 RFC6902 操作数。
- **导出补丁**：「导出 lang 补丁…」把编辑集与 vanilla 快照的差分生成
  `{"patchs": { "<相对路径>": [RFC6902 操作] }}`，默认写到模组目录
  （`<项目名>-lang.json`）——放进模组目录即被加载器在启动时应用
  （目标文件自动 .bak、退出还原）；报告会列出每个文件的操作数，
  「无差异」的文件明确注明未进入补丁。
- **直接应用到 lang 目录…**：显式警告后把补丁就地写回游戏 lang 目录
  （编辑器不负责备份/还原；真实加载器在启动/退出时才做 .bak）。日常流程请
  用「导出 lang 补丁…」。
- **索引缓存（只影响速度）**：浏览与搜索走 `<程序目录>/cache/text-index.db`
  这份表缓存（冷建索引要扫一遍全部 lang 文件，之后进页面直接读库）。
  缓存里只有原版事实（文件大小/时间/键数/是否 UTF-8 + 命中候选）；
  **编辑集与导出通道完全不碰缓存**，删掉这个库功能完全不受影响（只是变慢），
  搜索框旁的「清空缓存」可随时删库重建。换游戏目录、改 `config.json`
  （含切换活动语言）或改动某个文件，都会自动让索引失效重建。

## 6.3 静态数据工作台（🧩，plan-08）

活动栏 🧩 打开，布局同资源工作台骨架：

- **定位**：从游戏 catalog（`StreamingAssets/aa/catalog.bin` 或 `catalog_S1.bin`）
  **每次动态解析**出静态数据 bundle `static_s1_0_assets_all_<32hex>.bundle`
  的内层哈希与外层键，再找缓存条目 `<外层键>/<内层键>/__data`；
  缓存未命中时给出「启动一次游戏生成缓存后重试」的提示（不硬编码任何哈希）。
- **浏览列**：静态 bundle 内全部 TextAsset（数据类 = `m_Name` 里 `/` 前的部分，
  无 `/` 归「未分组」；表名 = `/` 后的部分），支持表名 / 键 / 值搜索。
- **编辑列**：与文本工作台同款的键值表 + 原始 JSON 编辑；「与官方版本的差异」
  实时显示 RFC6902 操作数；「还原此表」丢弃该表的修改。
- **导出**：「导出 .staticmod…」把修改集用 `StaticModService` 生成
  jsonpatch 补丁包（manifest 带 `container` 精确寻址 + `patches/*.json`），
  默认写到模组目录。**重打包 bundle 与 catalog 双写由真实加载器完成**，
  且需要在加载器里启用「静态数据 Mod」开关；编辑器只产出模组包，
  全程不写 catalog / 缓存 / 游戏目录。
- 静态 bundle 里的资源默认**不出现在资源工作台**（筛选行「显示静态数据表」
  可临时显示）。

## 7. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 字段编辑保存报 InvalidTarget | 同文件指针指向了不存在的 Path ID；用「自动填充」选择真实对象，或把 m_PathID 改回 0 |
| 构建报「重写后引用完整性检查失败」 | 某次重写把原本可解析的指针变成悬空；按提示的字段回退修改 |
| 无法读取 SerializedFile / Bundle | 文件损坏或不是 Unity 序列化文件；先用 CLI `probe` 探测 |
| 音频导出灰显 | 未配置 FMOD DLL 目录，或目录里缺少 fmod64.dll/fsbank64.dll；在「项目设置…」里用「检测兼容性」查看缺什么 |
| Sprite 按钮灰显 | 选中对象不是 Sprite 类型，或来源不是 Unity bundle/SerializedFile |
| 预览显示「没有专用预览形态」 | 该类型暂无专用预览；下方十六进制转储与「属性」区仍可用 |
| 音频试听报 FMOD 错误码 | 先用「设置 → 检测兼容性」确认 DLL 位数与接口；游戏自带 `fmodstudio.dll`（FMOD 2.x）已支持（按 DLL 版本传 headerversion），缺 FSBANK 时只能解码不能编码 |
| 静态工作台提示「缓存里还没有这个条目」 | 启动一次游戏让它下载/生成该 bundle 的缓存，再点「重新定位」 |
| .rebank 导出后加载器跳过 | 样本 wav 名必须与加载器从原版 bank 解出的名字一致；改用「导出整包 .bank…」更稳 |
| 导出报「目标被占用 / 无法写出」 | 输出文件被游戏或其他程序锁定；关闭占用程序（或以管理员权限）重试，原文件未受影响 |

## 8. 格式边界与合规

- Unity 解析全部经由 AssetsTools.NET，本工具不手写 Unity 二进制解析器。
- 不附带、不伪造任何 FMOD 二进制；运行时只绑定用户提供的 DLL 的公开 C ABI。
- 未经真实游戏样本验证的格式兼容性不会宣称；未支持的对象类型会明确报告而不是
  静默丢弃。
- FMOD DLL 检测只读取 PE 头与导出表（不加载、不执行任何 DLL 代码）。
